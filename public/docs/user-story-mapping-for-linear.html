User story mapping for Linear

3 min read

On this page
Import through the API Import a CSV file Review the import What you get on the story map Export to Linear

Bring a Linear backlog in, lay it out as a journey, then send the plan back. Projects, parent issues, statuses, estimates and labels all come with it.

  1. 1Linear API fetches the issues of a team straight from Linear.
  2. 2Linear CSV reads a CSV file exported from Linear.

Import through the API

  1. 1Choose Menu → Import → Linear → Linear API, or click Linear on the home page.
  2. 2Paste an API Key. The Create key link opens the page in Linear where you make one.
  3. 3Fill in the Team Key, the letters before the number in an issue ID: JAC from JAC-5.
  4. 4Click Fetch from Linear. Verify Connection checks the details first, if you want to.

Note. Your credentials aren't stored or logged. They go straight to Linear and are dropped when you're done.

Import a CSV file

  1. 1In Linear, export your issues as CSV. The import dialog shows the way: Settings > Export > Export CSV.
  2. 2In the story map, choose Menu → Import → Linear → Linear CSV.
  3. 3Drop the file in, or click to pick it.
  4. 4Click Continue.

The file needs a Title column. Issues from a CSV don't link back to Linear.

Review the import

Review Import lists every group with its issues. Untick anything you don't want, or click Deselect all and tick what you do. The count at the bottom shows what's going in.

Tag by picks how the issues group:

  • Group by projects makes each project a group, with its issues under it. Issues with no project go in Other (no project). Parent issues aren't imported.
  • Group by parent issues makes each parent issue a group, with its sub-issues under it. Issues with no parent go in Other (no parent issue).

It starts on projects when there are two or more, and on parent issues otherwise.

Importing into an open story map gives you a choice:

  • Add to existing map puts the imported cards to the right of what's there.
  • Replace map swaps the whole story map for the import, and asks first.

Either way, a backup is taken before anything changes. Click Import to Map to finish.

What you get on the story map

The cards land in a slice called IMPORTED: Projects & issues, or IMPORTED: Parent issues & sub-issues, with an empty MVP slice above it and a blank backbone.

  • Groups become lime green cards, tagged project-01 or parent-01 and so on.
  • Issues under a group become cards tagged with it, such as project-01-task, plus their Linear labels.
  • Descriptions go in the body of the card.
  • Statuses become done, in progress or planned.
  • Estimates become the points on the card.
  • Links open the issue or project in Linear.

The cards fill up to eight columns from left to right, so a group and its issues won't share a column. The tags keep them together: search and filter by project-01 to see one group at a time.

Tip. Now make it a story map. Name the users, activities and steps, then drag each card under the step it belongs to. Define the story map backbone shows how.

Export to Linear

Linear export goes through the API. Choose Menu → Export → Linear → Linear API:

  1. 1Under Releases, tick the slices to send.
  2. 2Under Status, tick the statuses to send.
  3. 3Each step becomes a parent issue, named after the step, with its cards as sub-issues. Rename a parent issue, add a description, or untick anything to leave out.
  4. 4Click Step 2: Credentials →.
  5. 5Paste an API Key and fill in the Team Key.
  6. 6Click Export to Linear.

A card body becomes the description of its sub-issue, and card points become its estimate. Statuses don't carry over. The progress list links to every issue as it's made. One export takes up to 200 parent issues and 2,000 sub-issues.
