Story map data links

2 min read

On this page
Get the data Inside a project What you get Where they're handy

Every user story map link doubles as a data link. Add .json, .yaml or .csv to the end and you get the story map as data instead of the app. No export, no download step, and it's never out of date.

Get the data

Take the link of the story map and add the format to the end:

  • storymaps.io/abc12345.json
  • storymaps.io/abc12345.yaml
  • storymaps.io/abc12345.csv

Open one in the browser, or fetch it from a script, such as curl https://storymaps.io/abc12345.yaml.

The .csv link downloads as a file, named after the story map, ready to open in a spreadsheet.

Inside a project

A story map opened from a project has a longer link, with the project in it. Add the format to the end of that link in the same way:

  • storymaps.io/p/k8f2m9xq/abc12345.yaml

What you get

The story map as it is at that moment, with every change up to then, in the same formats as Export a story map. The JSON and YAML start with the name of the story map, its ID, the site it came from and whether it's locked.

Backups aren't included, so whatever reads the link sees only the story map as it is now. To take the backups with you, export to JSON or YAML instead.

Where they're handy

  • AI tools. Build with AI points an AI tool at the .yaml link, so it reads the latest story map.
  • Scripts and reports. Fetch the .json or .csv link to pull the story map into anything else you use.
  • A spreadsheet. Open the .csv link for a fresh copy whenever you need one.

The links work on a locked story map too.

From the terminal

storymaps pull saves the YAML as a file, to edit and push back as a change to the story map. See Pull a story map.

Note. A data link has the story map link inside it, so it's best shared where you'd share the story map.
