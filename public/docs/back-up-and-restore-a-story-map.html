Back up and restore a story map

2 min read

On this page
Make a backup Restore a backup Backups the app makes Keeping backups Backups in exports

A backup is a copy of the whole user story map at one moment. Make one before a big change, and if the change goes wrong, one click puts the story map back.

Try it now

Back up and restore a practice story map.

Open practice story map

Make a backup

Open Menu → Backups and click Create Backup. Add a note, such as "Before the workshop", so you can tell it apart later.

  1. 1Create Backup makes a new backup.
  2. 2Restore puts the story map back to that backup.

Each backup shows its note, the name of the story map, how long ago it was made, its size and how many cards it has.

If nothing has changed since one of the backups, no new backup is made, and the app tells you which one matches.

A locked story map has to be unlocked before it can be backed up.

Restore a backup

Click Restore on a backup. The app backs up the story map as it is first, as Auto: before restore, so a restore can be undone too.

A locked story map has to be unlocked before it can be restored.

From the terminal

The CLI and the app share the same backups. storymaps backup makes one, and storymaps restore puts one back. See Back up and restore from the terminal.

Backups the app makes

As well as before a restore, the app backs up the story map before an import, as Auto: before import.

Keeping backups

The app keeps the 8 newest backups, and the oldest go as new ones come in. Backups are protected from deletion, but can be removed if needed by contacting us.

Backups in exports

Export a story map as JSON or YAML and its backups go with it. Import the file into another story map and the backups come too, marked as imported so you can tell them apart from the ones it already had.

The link to a story map, with .yaml or .json on the end, gives the story map as it is now, without its backups.
