Build an app from a story map with AI

3 min read

On this page

A user story map already says who the product is for, what they do and what goes in each release. Build hands all of that to an AI tool as one prompt, and the tool builds it. Pick a slice, pick your tool, copy the prompt and paste it in.

Product teams can build to learn. Put a working version of a slice in front of users, see what holds up, and change the story map before the team commits to the release.

Try it now

Build from a coffee app with an MVP and the releases after it.

Open practice story map

Why a story map makes a strong prompt

A request such as "build me a coffee ordering app" leaves the AI to guess who it's for, what they need and what comes first. A story map has settled those questions, and the AI reads it as a structured specification:

  • Users say who it's for.
  • Activities and steps give the journey, in order.
  • Tasks give the features under each step, most important first, with the detail in their bodies.
  • Slices set how much to build, and the goal of a slice says what it's for.

Build to learn

Each build takes a few clicks to set up, so a team can try an idea before committing to it.

  1. 1Build a slice as a prototype. Prototype an MVP with AI shows how.
  2. 2Put it in front of users.
  3. 3Add what you learn to the story map as new cards, and move cards between slices if the priorities change.
  4. 4Build again from the updated story map.

Tip. Keep the story map as the plan, whatever you build. Mark cards done once they're in the real product.

What you can build

  • Prototype an MVP with AI gets something people can click before anyone writes production code.
  • Build the next release with AI adds a slice to an app you already have.
  • Build one feature with AI tries a single idea from any slice.
  • Prototype a whole product with AI builds every release together.
  • Compare product directions with AI sets different tools or looks side by side.
  • Ask AI about a story map gets answers from an AI tool instead of a build.

Set up a build

Click Build at the top right of the story map. On a phone, it's the ⚡ button.

  1. 1Pick the AI tool you'll paste the prompt into.
  2. 2Storymap Slice picks what to build: one slice, or All Slices for the whole story map.
  3. 3Build Mode asks for a Prototype or a Full App. Coding agents can also Add to Existing App.
  4. 4Include map URL puts a link to the story map in the prompt, rather than the whole story map.

Add anything else the AI should know in Additional Instructions, such as the look and feel or the audience. Then click Copy Prompt. The line under the prompt says where to paste it.

Tip. Start with the first slice. It's the smallest version of the product that works from start to finish, so it makes a solid first build.

Pick the tool

  • App Builders: Lovable, v0, Replit, Base44 and Bolt. They choose the tech stack for you.
  • AI Chat: ChatGPT, Claude and Gemini. Prototype asks for a single HTML file that opens in a browser, and Full App lets the AI choose the tech and give you the code.
  • AI Coding Agents: Claude Code, Codex and Gemini CLI give you a command to run in your terminal, so the button reads Copy Command. Cursor, Windsurf and GitHub Copilot get a prompt for the agent chat in your editor.

How the prompt includes the story map

With Include map URL on, the prompt ends with the story map link as .yaml. The prompt stays short, and the AI reads the story map as it is when it opens the link.

Turn it off to put the whole story map in the prompt as YAML. ChatGPT and Gemini always get it this way, since they can't open links.

For Claude Code, Codex and Gemini CLI, Use npx storymaps has the command download the story map first, as storymap.yml in the folder you run it in, then start the agent on it. It uses the Storymaps CLI. Turn it off and the agent reads the .yaml link instead.
