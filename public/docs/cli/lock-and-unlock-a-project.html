Lock and unlock a project

2 min read

On this page

storymaps project lock locks the project, with the same two choices as Lock project in the app. See Lock a story map project for what a locked project does.

Lock it

Choose what the password locks, then type a password of at least 4 characters, twice:

  • The project keeps its name, story maps and order as they are. What's on each story map can still be edited.
  • The project and its maps also locks every story map that isn't locked yet. A story map with its own password keeps it.

--maps picks the second choice without asking, and --yes the first.

Lock story maps added later

A story map added after the project was locked isn't locked. --maps on a locked project asks for its password and locks only the story maps that aren't locked yet:

storymaps project lock --maps

See which story maps are locked

storymaps status ends each line with the lock that story map has:

locked means locked with the project password, and own lock means a story map with its own password.

Unlock it for your pushes

storymaps project unlock checks the password and saves it on this computer, as typing it in the app does. Then it asks whether to unlock the story maps that use the project password too, so pushes and backups don't ask for it:

--maps answers yes without asking. Everyone else still sees the project and its story maps locked.

Take the lock off

--remove takes the lock off for everyone, after a warning. It asks whether to take the lock off the story maps that use the project password too. The answer is no unless you say yes, as in the app:

--remove --maps takes them all off without asking.

One story map

storymaps lock and storymaps unlock work on one story map, named with -f. In a project folder without it, they say so:

See Lock and unlock a story map.
