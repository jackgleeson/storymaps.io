Use the CLI in scripts and CI

1 min read

On this page
Questions Passwords Lock a release from CI

The CLI only asks a question in a terminal. Run from a script, CI or most AI agent tools, there's no terminal, and every question has an answer you can give up front.

Questions

QuestionWith no terminalAnswer it up front
How much to do, such as one story map or the whole projectTakes the usual answer, and says so--yes
Before overwriting or removing something, such as Apply changes?Stops, and says to use --force--force
A passwordStops, and says how to give oneSee below

--yes never stands in for --force, so it can't overwrite anything by accident. Some agent tools do run commands in a terminal, so have agents pass --yes every time.

Passwords

Passwords are never options, as options end up in shell history and agent logs. They come from one of three places:

  1. 1Typed in a terminal.
  2. 2Remembered on this computer after storymaps unlock or storymaps project unlock --maps. Unlock once yourself, and an agent can push without ever seeing the password.
  3. 3STORYMAPS_PASSWORD, an environment variable, for scripts and CI. Set it from the secrets of the pipeline.

With none of them, a command stops before it changes anything:

With the variable set:

It works with every command that needs a password. For storymaps lock, it's the new password, so nothing is asked:

Across a whole project, the variable is only tried on the project and the story maps locked with its password. A story map with its own password is never sent the wrong one, which would count against the limit on wrong passwords.

Lock a release from CI

A pipeline can lock a project, and its story maps, once a release is agreed:

STORYMAPS_PASSWORD="$RELEASE_PASSWORD" storymaps project lock --maps

See Lock and unlock a project.
