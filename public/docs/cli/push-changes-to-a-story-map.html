Push changes to a story map

1 min read

On this page

storymaps push sends the changes in your file back to the user story map. They show in the browser, and in the activity log with the CLI icon.

storymaps push [target] [-f <path>] [--force]

Check, then push

  1. 1See what changed since the last pull.
  1. 2Push it. The CLI lists the changes again as it goes.

Steps, slices and cards that still match keep their IDs, so links to them keep working.

If it changed in the browser

When someone changed the story map after your last pull, the push stops, and nothing changes on the server:

The list shows what your push would do to the story map as it is now. Here, - V2: 1 card is a card someone added in the browser, which your file doesn't have.

To keep both:

  1. 1Copy your file, such as to mine.yml.
  2. 2Run storymaps pull, which brings in the changes from the browser.
  3. 3Make your changes again. storymaps diff storymap.yml mine.yml shows what they were.
  4. 4Push.

--force pushes anyway, and replaces what changed in the browser. Use it only when your file should win.

A locked story map

The CLI asks for the password, then pushes:

After storymaps unlock, it uses the saved password without asking. A script can give it in STORYMAPS_PASSWORD. See Use the CLI in scripts and CI.

For every story map in a project at once, see Push changes to a project.

A new story map

A file without an id makes a new story map on the first push. See Create a story map from the terminal.
