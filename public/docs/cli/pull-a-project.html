Pull a project

2 min read

On this page

storymaps pull with a project link downloads every user story map in the project into one storymaps folder, a file for each.

Pull it

Give it the link of the project:

storymaps pull [project link] [--dir <folder>] [--force] [--yes]

Each file is named by the ID of its story map, so renaming a story map in the app never puts a file out of step. The story map name is on the first line of each file.

The folder keeps a repo tidy: one new folder, however many story maps the project has. Pull it somewhere else with --dir, such as --dir plans.

The project key

Each file says which project it's in, straight after its id:

It's written only when the story map is fetched through its project. A plain link to the same story map leaves it out. Push ignores it, apart from adding a new story map to the project.

Pull again

Run storymaps pull with no link, from the folder that holds storymaps, or from inside it. Story maps added in the app get new files, and changes are listed before anything is overwritten:

One question covers every file. --force skips it.

A story map taken out of the project

A story map removed from the project in the app keeps its file. Pull takes the project line out, so a later push can't put it back by accident:

The CLI never moves, renames or deletes a file, so a story map open in an editor never looks deleted. Delete the file yourself when you no longer need it.

A link to one story map in the project

The address bar in the app always shows a story map inside its project, such as storymaps.io/p/k8f2m9xq/abc12345. Pulled with that link, the CLI asks whether you meant the story map or the whole project:

It only asks the first time. Once the folder holds the project, a link to one of its story maps pulls just that one. Run with no terminal, such as from a script, it takes just the story map and says how to pull the rest:

--yes does the same in a terminal, without asking.

Next to a single story map

A project in reach wins: storymaps below you, or project files in the folder you're in. A storymap.yml in the same folder is one -f storymap.yml away, and every command starts by saying so: Using the project in storymaps/. Add -f storymap.yml for the map in storymap.yml.

A folder with only storymap.yml works as it always has. To bring that story map into the project, see Start a project from the terminal.
