Edit the story map YAML

2 min read

On this page
How the file reads Change it Card fields Slice fields The rest of the file

Every user story map has structured data behind it, and storymap.yml is its source code. The file reads top to bottom the way the story map reads: the steps from left to right, then each slice with its cards under their step. Edit it in any text editor.

How the file reads

Part of the Coffee App, as it comes from a pull:

  1. 1The story map. Its name, its ID and the site it's on. Leave id and site as they are, so the push goes back to the same story map.
  2. 2Users and activities, the cards above the steps. Each one names the step it sits over.
  3. 3Steps, from left to right.
  4. 4Slices, from top to bottom. Each slice lists its cards under the name of their step.
  5. 5A card. Only name is needed.

Change it

In the Coffee App, mark Choose size done, and add a card to the V1 slice. The green lines are the new ones:

Keep the spaces at the start of each line as they are. YAML uses them to tell what belongs to what.

Then see what changed, and push it.

Card fields

FieldWhat it holds
nameThe title on the card.
bodyThe text inside the card, on one line or several.
statusdone, in-progress, planned or blocked.
pointsStory points, as a number. Each slice adds them up.
tagsA list, such as [payments, mobile].
colorThe card colour, as a hex code, such as "#fef08a".
urlA link, such as a ticket in a tracker.

Slice fields

FieldWhat it holds
nameThe name of the slice, such as MVP.
goalWhat the slice is for, in up to 200 characters.
targetDateThe date it's aimed at, as "2026-11-24".
collapsedtrue when the slice is folded away as finished.
closedReasonWhy it's finished: complete or closed.
storiesThe cards, under the name of their step.

The rest of the file

  • legend lists the colours of the legend, each with its label.
  • notes holds the text of the Notes tab.
  • A step called spacer is an empty column, for space between groups of steps.
  • locked says whether the story map is locked. Change that with storymaps lock.

Validate the file to check it before a push. A push checks it too, and stops before changing anything if it's not right.
