Start a project from the terminal

2 min read

On this page

storymaps project init starts a project, and storymaps project add adds user story maps to one. Both write the story maps into the storymaps folder.

Start a project

Give it a name, and the story map files to start from:

storymaps project init [--name <name>] [files...] [--dir <folder>]

Each file becomes a story map in the project. The files you started from are left as they are, so delete them once you've checked the new ones.

With no files, the project starts with one new story map, My Story Map. With no --name, it's called Untitled project, as in the app. Rename either in the app.

Add a new story map

storymaps project add [file or link] [--name <name>] [--project <link>]

It says the lock the story map has, so you know whether to lock it too. Adding to a locked project asks for the project password.

Add a story map you already have

Give it the file. A story map that's already on the server keeps its ID, its link and its activity log, and joins the project:

A file that isn't on the server yet, such as one you wrote yourself, becomes a new story map with its content. A story map you haven't pulled can be added by its link instead: storymaps project add storymaps.io/n5b8d2wq.

The next push creates it:

If another story map already has that ID, which is very rare, push gives the new one a fresh ID and renames its file to match. That's the one time the CLI renames a file.

Which project

project add adds to the project in the storymaps folder, or in the folder you're in. With no project folder yet, such as on a new computer, name the project with --project storymaps.io/p/k8f2m9xq.

Renaming a project, and reordering, removing and deleting its story maps, stay in the app. See Manage a story map project.
