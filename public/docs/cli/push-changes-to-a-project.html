storymaps push in a project folder checks every user story map, then pushes only the ones that changed.

Run both from the folder that holds storymaps, or from inside it.

Nothing is sent until everything checks out

Push checks every file, every conflict and every password before it sends anything. If one story map fails a check, none are pushed, so a project never ends up half pushed.

Locked story maps

Story maps locked with the project password need it once, for all of them. After storymaps project unlock --maps, it isn't asked for at all. A story map with its own password asks for that one separately.

Run with no terminal, such as by an agent or a script, push can't ask, so it stops and says how to give the password:

See Use the CLI in scripts and CI for STORYMAPS_PASSWORD.

Files push leaves alone

  • A file whose story map isn't in the project, such as one removed in the app, is skipped, and push says how to add it back with storymaps project add.
  • A file whose story map is no longer on the server, because it was deleted, is skipped too. A deleted story map never comes back at its old link.
  • A file without an id stops push, as it isn't on the server yet. Add it with storymaps project add.
  • YAML files without a project line, such as a docker-compose.yml, aren't story maps in the project, and push never looks at them.

To push one story map on its own, name its file: storymaps push -f storymaps/m7q2r8tz.yml.
