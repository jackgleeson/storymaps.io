Back up and restore from the terminal

2 min read

On this page

A backup is a copy of the whole user story map at one moment, kept on the server. The CLI and the app share the same backups, so one made in the terminal shows in Menu → Backups in the app, and the other way round.

Make a backup

Add a note with -m, so you can tell it apart later:

If nothing has changed since one of the backups, no new one is made, and the CLI says which one matches:

List the backups

Newest first, each with the ID to restore it by:

Restore one

Give it the backup ID. It shows the backup and asks first. --force skips the question.

  • It backs up first. The story map as it was before the restore becomes a backup too, so a restore can be undone with another restore.
  • It changes the story map, not your file. Run storymaps pull afterwards. Until you do, a push stops with a conflict, so an old file can't undo the restore by accident.

Keeping backups

The server keeps the 8 newest backups of each story map, and the oldest go as new ones come in. Backups are protected from deletion, but can be removed if needed by contacting us.

A locked story map needs its password to back up or restore. The CLI uses the one saved by storymaps unlock, or asks for it.

A whole project

In a project folder, storymaps backup backs up every story map with the same note, such as before an agent makes a big change:

A story map that hasn't changed since its last backup reuses it, so it doesn't use up one of its 8. A project password is asked for once.
